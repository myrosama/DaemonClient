# Code of conduct

## The short version

Be decent. Assume the other person is trying to help. Argue about code, not
about people.

## What is expected

- **Disagree technically.** "This breaks when the token has no dot" is useful.
  "This is amateur work" is not, and it also contains less information.
- **Assume competence.** Someone asking an obvious question has usually already
  tried the obvious thing.
- **Be direct about problems.** Softening a real security finding to spare
  someone's feelings helps nobody, least of all the users. Say the thing, say it
  plainly, and say it about the code.
- **Accept a no.** Not every good idea fits this project. The [roadmap](docs/ROADMAP.md)
  lists things that are deliberately not planned and why.

## What is not

Harassment, personal attacks, discriminatory language, sustained disruption,
publishing someone's private information, or unwelcome attention of any kind.
This applies in issues, pull requests, commit messages, and anywhere else the
project is discussed.

## Reporting

Email the maintainer via the address on the [GitHub profile](https://github.com/myrosama),
or open a GitHub Security Advisory if the matter is sensitive. Reports are
handled privately.

This is a small project without a moderation team. What that means in practice:
you will get a human reply rather than a process, and the maintainer's decision
is the final one. Responses range from a conversation to a permanent ban,
depending on severity.

## Scope

Project spaces, and public spaces when someone is representing the project.
